# Spec Delta

## Purpose

讓使用者以明確時間來源、安全可得性及可重現控制回看 CSV 歷史，僅顯示當時已取得的製程與品質資訊，同時保留固定 SPC、獨立 What-if 及後續正式資料整合的邊界。

## ADDED Requirements

### Requirement: REPLAY-01 單一游標與共同可見範圍

系統 SHALL 以單一游標管理目前篩選來源的回放位置，依可信可得時間排序並將同時刻事件視為單一步進單位；所有功能 MUST 使用相同截止及來源版本，保留原事件時間、批號、卷別與材料區段識別。

#### Scenario: 同時事件原子推進
- **GIVEN** 多筆事件具有相同可信可得時間，另有較晚事件
- **WHEN** 單步前進
- **THEN** 一次釋出完整同時事件群，順序可重現，不拆成中間可見狀態，也不釋出較晚事件

#### Scenario: 製程與品質分次釋出
- **GIVEN** 同一材料的製程早於品質結果可得
- **WHEN** 推進至兩者之間
- **THEN** 已可得製程可顯示，品質仍不可用；後續品質釋出沿用原材料識別，不當成新製程區段

#### Scenario: 同一截止供所有功能使用
- **GIVEN** 回放游標已有可見資料
- **WHEN** 摘要、側欄、SPC、Alarm、What-if 選單、圖表及資料檢查刷新
- **THEN** 使用同一截止與版本，各功能僅消費相依且已可得欄位，不各自推進或讀取未播放列

### Requirement: REPLAY-02 可重現播放控制

系統 SHALL 提供播放／暫停、單步、重新開始及回放倍率；暫停保留進度，單步僅前進一個原子單位並暫停，到終點自動停止。一般重跑或重複計時通知 MUST 不重複推進。倍率不得修改製程線速或模擬設備控制。

#### Scenario: 暫停與單步
- **GIVEN** 回放已推進但尚未結束
- **WHEN** 暫停、等待後單步
- **THEN** 等待期間不變，單步只前進一群並維持暫停，固定 What-if 候選不變

#### Scenario: 計時與重跑去重
- **GIVEN** 正在播放且相同計時通知已處理
- **WHEN** 切 Tab、操作欄位或重送通知
- **THEN** 不重複消費通知；新的到期時間才推進，若跨多群則保留各群順序與應產生的異常，不跳掉中間事件

#### Scenario: 倍率與線速分離
- **GIVEN** 有未播放事件且 What-if 有線速候選
- **WHEN** 選擇 0.5、1、2 或 4 倍並繼續播放
- **THEN** 只改變歷史時間前進速率，切換時保留當前進度，不補算暫停時間，不修改實測或候選線速

#### Scenario: 終點停止
- **GIVEN** 最後一群事件尚未播放
- **WHEN** 播放到終點或在終點再按播放／單步
- **THEN** 自動停止且進度不超界，不自動重新開始；空資料控制停用並說明原因

### Requirement: REPLAY-03 模擬時間與進度

系統 SHALL 顯示目前模擬時間、已播放來源筆數、總筆數及進度，區分可得時間軸與原事件／量測時間。品質的延後釋出不得重複計為新來源列；未開始及空範圍不得顯示虛構觀測。

#### Scenario: 起點空狀態與終點
- **GIVEN** 已建立有效回放範圍
- **WHEN** 尚未播放、播放中或已結束
- **THEN** 分別顯示尚未播放／目前時間／結束狀態，筆數及進度與游標一致，起點不提前顯示第一筆數值

#### Scenario: 來源筆數與事件群不同
- **GIVEN** 同一來源列有多次欄位釋出
- **WHEN** 品質晚於製程釋出
- **THEN** 已播放來源筆數僅計該列一次，另可顯示事件群進度，不以品質事件重複增加總列數

#### Scenario: 篩選時間與釋出範圍
- **GIVEN** 時間篩選以原有事件時間選定材料，而其品質較晚可得
- **WHEN** 顯示回放範圍並播放到該品質可得時刻
- **THEN** 同時標明材料選取時間窗與可得時間軸，允許該材料的晚到結果於正確時刻釋出，不因原篩選終點而靜默丟失，也不加入篩選外材料

### Requirement: REPLAY-04 不使用未來資料

系統 MUST 對每個欄位及品質目標遵守可信可得截止，未來實測值、旗標或衍生資訊不得影響當下畫面與分析；模型輸入及解釋來源亦須符合歷史適用條件。不可用時 SHALL 局部降級，不阻止其他可靠功能。

#### Scenario: 未來資料擾動不變性
- **GIVEN** 兩份資料僅在尚未可得的數值及品質結果不同
- **WHEN** 在相同截止檢視所有 Tabs、側欄、原始預覽及資料問題
- **THEN** 當下數值、可見問題、統計、圖表及 Alarm 相同；只允許檔案結構、總筆數及來源版本等選取中繼資料預先顯示，不暴露未來值或品質分布

#### Scenario: 子組尚未完整可得
- **GIVEN** 某目標子組只有部分有效試片已可得
- **WHEN** 重算 SPC
- **THEN** 不回讀未來試片或以其他列補組，不產生該組判定，並依既有規則保留無效／缺組邊界

#### Scenario: AI 必要特徵未可得
- **GIVEN** 最新製程區段有某目標必要特徵尚未釋出
- **WHEN** 更新監控預測或選作新 What-if 基準
- **THEN** 相依目標顯示輸入不可用原因，不借用未來特徵；晚到舊品質不將監控對象倒退為較舊製程區段

#### Scenario: 歷史 SPC 基準保持固定
- **GIVEN** 獨立且早於回放起點的歷史基準通過既有適用檢查
- **WHEN** 推進、暫停或重新開始回放
- **THEN** CL／UCL／LCL 不變，與相同已可得切片的快照分析一致，不用回放資料重估基準

#### Scenario: 模型與背景歷史適用性不足
- **GIVEN** 正式模型或 SHAP 背景的歷史適用宣告不足，或測試 Payload 含未可得樣本
- **WHEN** 請求歷史當下預測／解釋
- **THEN** 受影響能力顯示待 C9／不可用並拒絕不符資料，不暗示無前視偏差；確定性 Mock 的示範與無 SHAP 能力標示仍保留

### Requirement: REPLAY-05 固定情境與重啟有效性

系統 SHALL 只允許主動選擇已可見區段作為 What-if，保留固定時刻的輸入、環境、識別及候選；回放更新不得改寫。重新開始後舊情境 MUST 明示失效並停止顯示其比較結果，重新變可見也不得自動恢復，須由使用者主動選定。

#### Scenario: 情境固定但監控繼續
- **GIVEN** 已固定一個可見區段並調參
- **WHEN** 回放推進至新材料
- **THEN** SPC、摘要及監控 Alarm 繼續更新，What-if 批號／卷別／MD／時間與候選保持不變，不冒充最新監控結果

#### Scenario: 同區段晚到欄位
- **GIVEN** 已固定區段的原始特徵版本
- **WHEN** 該區段晚到品質或其他欄位
- **THEN** 固定基準與候選不被靜默補值或改寫，只有主動更新基準才使用目前已可得上下文並使舊結果失效

#### Scenario: 重新開始使選區失效
- **GIVEN** 已有 What-if 選區及結果
- **WHEN** 重新開始回放
- **THEN** 游標回零並暫停，選區標示不在可見範圍、控制停用，舊預測／建議及未來參數值不再呈現；不默認換成首筆未播放材料

#### Scenario: 不自動復活與主動重選
- **GIVEN** 重啟前選區曾失效而現在再次可見
- **WHEN** 回放繼續或使用者主動重新選取
- **THEN** 僅繼續播放不恢復舊情境；主動選取後以當下可見輸入建立新基準、重設候選及重新計算

### Requirement: REPLAY-06 來源與工作階段生命週期

系統 SHALL 在成功更換來源、映射、時間 profile、版本或材料篩選時建立新回放範圍並暫停歸零；同源重載、失敗載入、一般重跑及 Tab 切換須保留有效進度。舊範圍計時或計算結果 MUST 不寫回新狀態。

#### Scenario: 新來源或篩選
- **GIVEN** 回放已有進度
- **WHEN** 成功更換來源／映射／時間設定版本或批號／時間篩選
- **THEN** 舊計時與相依結果失效，新範圍游標為零並暫停；What-if 依來源及可見性規則失效，不改寫原始資料

#### Scenario: 同源與失敗嘗試
- **GIVEN** 有效回放正在使用
- **WHEN** 相同內容與相同設定重載或另一次載入失敗
- **THEN** 保留有效來源、進度、暫停／播放狀態與匹配結果，不以失敗來源替代

#### Scenario: 快照與回放切換
- **GIVEN** 使用者在快照與回放間切換
- **WHEN** 進入回放或離開回放
- **THEN** 進入時從零暫停並使不可見選區失效；離開時停止計時並恢復快照完整篩選視圖，但不自動復活已失效情境，SPC 基準版本不變

#### Scenario: 過期通知與結果
- **GIVEN** 舊範圍的計時或圖表／模型結果尚未完成
- **WHEN** 重啟、更換來源或切換模式後才抵達
- **THEN** 不推進新游標或覆寫新結果，相同範圍相同通知亦不重複處理

### Requirement: REPLAY-07 明確時間與逐目標契約

系統 MUST 區分事件、製程完成、量測及結果可得時間，消費版本化且可追溯的來源時間映射與逐目標 availability，不將整體旗標等同五目標可用。不可信時間或未決檢驗版本僅使相依資料不可用，不在 C 建立七表 JOIN、重測選取或正式時間契約。

#### Scenario: C 專用時間測試設定
- **GIVEN** 明確標示 C Mock 且其 profile 聲明列內欄位的釋出規則
- **WHEN** 以該 profile 回放
- **THEN** 依其明示時間重現，不將 C 假設套用其他來源，也不宣稱真實產線時間驗證完成

#### Scenario: 逐目標結果晚到
- **GIVEN** 不同品質目標具有不同可信結果可得時間及旗標
- **WHEN** 只有部分目標已可得
- **THEN** 僅釋出該部分，保留來源／scope／方法與版本，外觀旗標衝突及未決重測仍不可用，不能用整體 availability 放行五目標

#### Scenario: 正式時間資料不足
- **GIVEN** 來源缺可靠發布時間、欄位時間或只有 loader 的 AVAILABILITY_ASSUMED
- **WHEN** 嘗試歷史回放
- **THEN** 顯示受限欄位與待確認映射，不將 timestamp 或檢驗 completed_at 自動視為發布時間；可證明可得的其他欄位仍可回放，無可用事件時停用回放而保留快照檢查

#### Scenario: 時間矛盾與檢驗修訂
- **GIVEN** 時區未知、發布早於相關事件／完成／量測，或只有未來選定的最終重測而無當時版本證據
- **WHEN** 驗證時間投影
- **THEN** 回報具體來源與目標，拒絕相依歷史資料，不猜時區、不以取最大時間修補、不將未來重測回填歷史；其他可靠通道維持可用
