# Spec Delta

## MODIFIED Requirements

### Requirement: DATA-02 驗證與功能適用性分離

系統 MUST 檢查必要欄位、時間、有限數值、物理範圍、缺值、重複與識別，回報 code、field、row、message；原值與空白／單位／排序正規化資訊 SHALL 可追溯。品質不足不妨礙可用預覽，候選輸入完整度不代表 SPC 適用或模型可推論；SPC 須另經逐目標子組／基準驗證，其他有效目標不因局部缺資料停用；禁止補造量測或猜單位／時區。

#### Scenario: 部分品質未量測
- **WHEN** 有效識別與製程資料存在，但部分或全部品質欄位缺失
- **THEN** 缺品質欄保持缺欄、原有效資料可預覽，各品質／特徵／子組識別完整度分別回報，缺量測目標不生成 SPC 判定，不補造模型預測；其他目標通過 SPC 適用性與基準檢查後可判定

#### Scenario: 型別或物理範圍錯誤
- **WHEN** 時間無效、數值非有限、濕度超過 0～100、線速非正數，或列存在缺值／疑似重複
- **THEN** 指出來源列與原因，保留原始值供追溯，無效值不被替換為合法值；重複列保留供檢查但不計入候選有效輸入

### Requirement: DATA-03 C 專用 Mock 與來源契約隔離

系統 SHALL 提供固定 seed／版本可重現的 C 專用 fixtures、metadata 與示範設定，包含同次獨立試片、可配置子組及早於監控且 ID 不重疊的獨立歷史資料。歷史資料只有通過版本化適用性與穩定性檢查後才能建立 C Mock SPC 界限，不能宣稱真實產線界限；C Mock 欄位／子組大小 MUST 不成為 A 正式 CSV 必要契約。

#### Scenario: Mock 與其他來源結構不同
- **WHEN** 上傳來源沒有 C Mock 的子組或區段欄位
- **THEN** 仍可載入有效識別資料並回報缺少的候選輸入／本地識別限制，不自動湊連續五列、不要求 A 改格式，也不產生 X-bar 判定

#### Scenario: 已知異常與無效資料情境
- **WHEN** 載入 C 的正常、偏移／趨勢／同側、缺欄、缺值、無品質或無子組 fixtures
- **THEN** 來源／版本及預期資料可追溯，重建內容一致；預期真值在 metadata，SPC 只由實測值與有效基準／規則算出結果，再與測試真值比對；不直接以情境檔名／標籤生成警報，也不宣稱模型測試完成
