# Design

## Context

C1＋C2 已歸檔，現有主規格只有 dashboard-workspace／csv-ingestion。app.py 組合 ui/layout.py；側欄先載入與篩選，overview／tabs 尚無 SPC。LoadResult 保留原值、identity_valid、duplicate_record、來源列、available_at；selected_rows 回傳篩選副本。C2 input_eligibility 只有候選輸入計數，不能取代統計適用性。WorkspaceState 目前沒有 SPC 結果；model.baseline_version 也不能當有效基準物件。

現有 c_mock 有 30 個監控子組、25 個事前歷史組、每組五個獨立模擬試片，產品／配方及設定可核對；metadata 明寫基準尚未驗證。C2 測試包含 fixtures bytes 重建與占位預期。這些是觀察到的現況，不代表本案已實作。

依據 ADR-005／006、ADR-010／014／015 與 [C3 計畫](../../../../docs/change-plans/fccl-spc-monitoring.md)。四個新 SPC 需求承接原完整規劃的快照片段；原情境的跨階段落點見 D8。ADR-003／012、TCP-001～004 狀態不變。

## Goals / Non-Goals

**Goals:** 純計算、逐目標降級、固定基準及可重現事件；單一計算結果供 SPC Tab／主 Alarm 共用；不改資料載入與篩選語意；每組功能自帶單元／UI／指南驗證，可獨立 Archive。

**Non-Goals:** 不新增 I-MR／R／S 顯示圖；R 只作基準內部估計／穩定性檢查。不實作模型預測 Alarm、風險門檻、具體調參建議、可操作 What-if、圖表解釋或定時回放。不改 A／B、正式品質值、主 specs 或歸檔歷史；本輪不改 Python。

## Decisions

### D1. 邊界與預計模組

| 預計位置 | 責任與理由 |
|---|---|
| c_dashboard/spc/types.py、config.py | 不可變基準／規則／結果型別與 C 來源設定，與模型狀態分離 |
| c_dashboard/spc/subgroups.py | 依明確取樣契約逐目標驗證完整組；保留無效組作序列屏障 |
| c_dashboard/spc/baseline.py | 歷史適用性、穩定性、固定界限與基準識別，不讀監控品質擬合 |
| c_dashboard/spc/rules.py、service.py | 純規則、事件與四目標一次性分析；不依賴 Streamlit |
| c_dashboard/ui/spc_panel.py、spc_alarm.py | 圖形／表格、紅字事件、限制提示，共用分析結果 |
| ui/layout.py、overview.py、tabs.py、state.py | 小幅組合接點、C3 成熟度及獨立 SPC 狀態；不把計算塞進 app.py |
| data/fixtures.py（必要的局部延伸） | 依顯式 C profile 載入獨立 history，沿用現有 parser，不更動生成器 |
| tests/fixtures/c_spc/、tests/test_c3_*.py | SPC profile、手算／邊界測試樣本與預期值；保留 c_mock 原始 bytes |

不用新 HTTP／DB，也不依賴 B 模型。繪圖優先以 Streamlit 原生 Vega-Lite 接點疊合圖層，不新增繪圖依賴；若相容性測試顯示需要額外工具，先提出具體限制再調整。UI 控制與純函式分離，比 app.py 一體化更容易驗證前綴與不可變性。

### D2. 明確的 C 取樣／條件契約

C profile 為本案測試設定，不是 A 正式 schema。包含 profile_id／version、資料／歷史檔雜湊、品質單位、product_id／recipe_id、subgroup_size、獨立試片取樣聲明、組鍵與試片鍵、條件欄位及容差、取樣間隔／順序依據、monitoring_origin、歷史最小組數、常數／規則版本。

預設五試片、至少 25 歷史組只是 C 配置；支援常數表 n=2～10，另用 n=3 測試變更大小。未知 n 不沿用 0.577，回報 UNSUPPORTED_SUBGROUP_SIZE。不同 n 混在同一基準內不採變大小界限；依來源設定先分開或標不適用。

組鍵以資料集＋批號＋subgroup_id 定位；同組須同產品／配方／材料區段／取樣時間／受控設定，且有恰 n 個不重複 specimen_id。受控設定包含線速、塗佈溫度／間隙／黏度、熟化溫度／時間、壓合溫度／壓力／時間；C Mock 容差為 0。環境觀測可因試片有小幅差異，僅依 profile 聲明的適用範圍檢查，不把每個環境差值當換製程。

完整性先檢查包含壞值／重複的原組，再依目標驗證有限量測；不先 dropna、去重或用 identity_valid 篩到只剩可湊的列。共同識別／條件錯誤使整組無效，只有某目標缺量測則只影響該目標。保留每組的 status／reason／source_rows 與時間屏障；空組／完全缺組由明確間隔或序號發現，不能只看剩下列數。C Mock 宣告每分鐘一組；未知來源缺相鄰性證據時可顯示單點，不累計跨未知邊界的連續規則。

上傳 CSV 預設只有 C2 mapping，不因欄名相同或產品字串相同自動信任 C Mock 的取樣／基準。分析接點允許顯式外部來源 profile，但正式適用證據留 C9；C3 UI 至少支援已登錄 C Mock。無 profile 的上傳仍可查看原始量測／問題，SPC 顯示缺依據，無需新增正式 CSV 必填欄。

### D3. 固定歷史基準與穩定性政策

歷史從獨立 history.csv 載入，不使用目前側欄篩選後的監控檔作校準。逐目標要求至少配置組數的完整有效歷史組；宣告校準窗內若有無效組，整個目標基準拒絕，不自動挑乾淨子集。history 的最大 available_at 嚴格早於固定 monitoring_origin（整個來源的監控起點，非目前篩選起點），歷史取樣亦在起點之前。比較來源內容與原生批號／試片識別及時間，拒絕同一觀測換了檔名或 source_id 後混入歷史。

產品／配方／受控條件／品質目標／單位／n 必須相容；歷史可跨相容批號匯總，但 6／9 規則在換批與缺組處中斷。組內範圍平均為零則不建立基準；少數單組 R=0 不等於整體 R-bar=0，仍需照穩定性規則驗證。

CL = mean(各完整歷史子組均值)，R-bar = mean(各歷史子組 max−min)，UCL／LCL = CL ± A2(n) × R-bar。不將 MD／TD 或其他界限截成 0；原始精度做判斷，僅畫面格式化。產品規格不是這些界限。

手算驗收例：25 個不同識別的 n=5 子組均為 [1.23, 1.24, 1.25, 1.26, 1.27]，預期 CL=1.25、R-bar=0.04、UCL=1.27308、LCL=1.22692；此人工樣本只測公式與規則，不宣稱模擬完整製程分布。另以全負的尺寸子組測負 CL／LCL 保留。

C Mock 穩定性政策 c-spc-stability-v1：先用全部宣告歷史算暫定統計，檢查組內 R 在 D3(n)×R-bar～D4(n)×R-bar 內，再檢查 X-bar 嚴格超界、六點嚴格趨勢與九點同側；任一失敗拒絕該目標並列出原因。這是 C 模擬篩檢，不證明真實製程統計假設或獨立性成立；不新增 R 圖。常數採 [NIST X-bar／R 說明與表格](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc321.htm) 的同一版本（n=5：A2=0.577、D3=0、D4=2.115；n=3：1.023、0、2.575），來源與有效位數記入 profile。6／9 是既有 C 規則預設，不宣稱該 NIST 表提供本案全部趨勢政策。

歷史與監控共用 rules.py 的無狀態比較／連續序列核心；任務 3.3 先建立並測試核心及歷史組合，4.1 再組合監控事件語意，不讓基準驗證依賴尚未完成的監控 UI／service，也不複製兩套有差異的 6／9 判定。

凍結的 BaselineBundle 保存目標、版本、歷史內容指紋、適用條件、校準時間窗、n／組數／常數、穩定性結果及 CL／UCL／LCL。版本由內容及 profile／算法版本決定；篩選、追加監控、切 Tab 不改它。新來源先重新核對適用性；僅明確更換獨立歷史或設定才形成新版本，不能靜默重新估計。

### D4. 純計算、狀態與未來回放接點

以下為 C 內部規劃 port，不要求 A／B 採同名 API：

| 操作 | 顯式輸入 | 輸出 |
|---|---|---|
| build_baseline | history_rows、history_profile、monitoring_origin | 不可變 BaselineBundle／逐目標問題 |
| compute_spc | visible_rows、source_context、baseline、rules、analysis_scope_id | SpcResult：四目標組統計／限制、事件、最新狀態、截止、來源版本 |

compute_spc 不讀檔、不讀全域 DataFrame／Session State、不接受模型候選作實測；呼叫者傳什麼切片就只能分析什麼。C3 以 selected_rows 副本呼叫；C7 將來傳共同可見前綴，同樣基準與規則即可重用，但本案不實作 timer／游標控制。

layout 在側欄處理完成後建立一次 SpcResult，將同一物件傳至 overview 與 tabs；四目標一起計算，不以 UI 所選目標限制上方警報。新增獨立 SpcState／基準資源接點，模型未接入不遮蔽實測警報。事件列表由目前分析純結果取代，不維護隨 rerun 追加的全域隊列。

結果鍵含 source_id／mapping、批號與時間篩選、profile／baseline／rule 版本；切目標只改呈現。成功換來源或篩選變更時舊結果立刻失效，無效匯入仍保留舊有效資料／SPC；不能顯示舊批次警報為新批次。基準不因篩選改變重估。共享快取僅可存不可變歷史資源，Session 狀態不能互相污染。

### D5. 規則、事件與狀態語意

以四目標各自的時間有序完整組判定。界限外使用嚴格 >／<；六點需五次嚴格同方向差值；九點需九個嚴格同側。等值中斷嚴格趨勢、等 CL 中斷同側；有效超界點仍可參與其他規則，不任意消除證據。無效／缺組、換批、條件變更中斷全部連續序列，單純時間排序不能消除屏障。

每個符合的滑動視窗於末端組建立事件，故六點與第七點各可有事件；同組多規則保留不同事件。ID 由 source／analysis_scope、baseline／rule 版本、目標、規則及觸發組組合，不含目前切 Tab 次數。payload 包含批號／區段／組、觸發時間（組內最大 available_at）、均值、相關 CL／UCL／LCL 或序列、規則說明與來源列。沒有外部通知／ack／機台動作。

最新狀態與範圍內事件分開：最新組無效為無法判定，即使較早有有效組；不得用舊有效均值冒充最新。圖上與表格仍保留較早事件。上方區塊列所有目標限制與範圍內實測事件，有事件則紅字；沒有事件但有缺失不能顯示全域正常。完全可判定且無事件時只稱「未偵測所啟用規則訊號」，不代表單件品質合格。

### D6. 圖形與畫面組合

維持原單頁／四 Tabs。SPC Tab 提供四連續目標選擇、X-bar 同圖的子組均值折線與原始試片量測點、CL／UCL／LCL 水平線、異常標記與明細。原始點是實測背景，不套子組平均界限當個別合格標準。缺／無效組留斷線與原因；不把兩側折線或趨勢跨越缺組連起來。

基準來源／版本／條件／n／組數／時間窗、資料截止、規則版本可查。規格如需呈現僅另列明示 C 示範表，不作 SPC 界限，也不添加正式數值。無有效基準仍可畫原始量測，但不畫有效控制線／警報；空資料有空狀態。

上方四連續摘要標示最新可判定與最新組的區別，以最新組有效均值顯示並標實測子組平均／時間，無效為「—」。外觀預測風險保持「—」；SPC 區另以文字顯示有效 appearance_ng 標籤數／NG 數，無資料就說明，沒有風險門檻／屬性管制圖。用 Streamlit 原生 error／顏色文字呈現紅字實測 Alarm，保留模型未接入提示，不能以其覆蓋實測事件。

### D7. 測試與現有相容性

- 單元：手算小樣本、n=3／5／不支援 n、正負 MD／TD、組大小錯誤／重複／跨條件、缺目標、歷史時間／識別重疊、穩定性失敗、零變異、固定界限、六／九首次觸發與相等／中心／缺組／換批、同組多規則、可重現／去重。
- 前綴契約：相同傳入前綴而外部未提供資料不同，SpcResult 相同；傳入缺試片前綴不能補齊；篩選前先發生的點不拿來湊當前六／九視窗。只證明純計算接點，不標記 C7 完成。
- 局部整合：同一結果送兩區、all-target events、來源／篩選／無效匯入／Tab 狀態、候選參數替身不改實測；完整 C1／C2 回歸及 Streamlit 啟動／匯入。
- AppTest：正常／偏移／趨勢／同側／部分品質／無品質／未知來源／空篩選，驗證圖表 payload 的線名與數值、事件識別與紅色訊息；空畫面測試保留，不以全域「所有 metric 永遠為 —」阻止已授權實測呈現。僅更新相應占位預期，不削弱載入／狀態／無虛構模型的斷言。
- 指南：說明 Mock、適用性、最新／歷史事件、原始點與子組均值、不可判定、非合格保證及後續邊界；本案驗收矩陣新增 docs/C3_SPC_ACCEPTANCE.md（Apply 時建立），不可改 C1＋C2 已歸檔驗收歷史。

## Risks / Trade-offs

- [模型未接入提示遮蔽 SPC] → 分離實測結果與 Adapter 狀態，同一結果供兩區。
- [刪掉壞列造成假連續] → 保存無效組／缺組屏障，測重複、過大、缺值與時間間隔。
- [歷史不穩定或篩選後重估] → 凍結內容版本、逐目標拒絕、無自動修剪歷史；固定 origin。
- [取樣獨立性／分布未證實] → 只聲明 C Mock 前提，不以機械檢查證明正式製程；正式適用性留 TCP／C9。
- [基礎規格仍說不可計 SPC] → 完整 MODIFIED WS-01～04／DATA-02～03，保留全部原情境名稱；不改主 specs／archive。

## Migration Plan

Propose 只新增本 Change artifacts 與追蹤紀錄。獲授權 Apply 後依 tasks 增加純模組與局部組合，保留現有 C2 載入／篩選／bytes；無 DB 或 A／B 資料遷移。失敗時顯示原資料檢查及局部不可判定，不回退為假正常。驗收／strict 通過後再由使用者決定 Archive，不能等待 C7／C9 才算 C3 完成，也不能將它們提前同步。

## Open Questions

沒有阻礙 C3 Mock 開發的未決跨組問題。正式取樣／頻率／來源、真正基準與品質規格仍由 TCP-001～004 及 C9 交接；I-MR 尚未批准。D2～D6 的配置與穩定性政策是供本案審閱的 C 內部實作預設，非正式團隊契約；若 Apply 證據揭露衝突，記具體原因並更新對應規劃，不擅自改原功能。
