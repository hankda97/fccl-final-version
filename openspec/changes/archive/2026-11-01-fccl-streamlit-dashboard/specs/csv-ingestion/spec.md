# Spec Delta

## Purpose

讓成員 C 使用明確標示的可重現 Mock 或上傳 CSV 完成獨立的資料載入、來源轉接、輸入驗證與預覽，保留原始值及錯誤追溯；測試設定不強加其他成員，也不以載入成功宣稱正式資料或模型已整合。

## ADDED Requirements

### Requirement: DATA-01 CSV 載入與可追溯識別

系統 SHALL 解析 UTF-8／BOM CSV，回報格式／編碼／表頭／列寬錯誤，保留來源名稱、原始 bytes／字串及列號。有效資料 MUST 具有可解析且時區明確的時間與批號，提供可追溯樣本／區段識別、可得時間穩定排序與批號／含端點時間篩選；本地區段與時間假設須提示。

#### Scenario: 未排序的有效資料
- **WHEN** 載入可映射且時間帶時區的未排序 CSV，並選擇批號／時間範圍
- **THEN** 依可得時間及來源列穩定排序並提示，篩選只保留符合資料且原識別不變；空交集可顯示空結果

#### Scenario: 無法解析的檔案
- **WHEN** 檔案為空、非 CSV、編碼／格式無效，或缺少必要時間／批號而無有效識別列
- **THEN** 回報具體匯入錯誤並保留先前有效資料及篩選，不把半完成結果提交為有效來源

### Requirement: DATA-02 驗證與功能適用性分離

系統 MUST 檢查必要欄位、時間、有限數值、物理範圍、缺值、重複與識別，回報 code、field、row、message；原值與空白／單位／排序正規化資訊 SHALL 可追溯。品質不足不妨礙可用預覽，只呈現各用途候選輸入完整度，不代表 SPC 適用或模型可推論；禁止補造量測或猜單位／時區。

#### Scenario: 部分品質未量測
- **WHEN** 有效識別與製程資料存在，但部分或全部品質欄位缺失
- **THEN** 缺品質欄保持缺欄、原有效資料可預覽，各品質／特徵／子組識別完整度分別回報，不生成 SPC 或預測結果

#### Scenario: 型別或物理範圍錯誤
- **WHEN** 時間無效、數值非有限、濕度超過 0～100、線速非正數，或列存在缺值／疑似重複
- **THEN** 指出來源列與原因，保留原始值供追溯，無效值不被替換為合法值；重複列保留供檢查但不計入候選有效輸入

### Requirement: DATA-03 C 專用 Mock 與來源契約隔離

系統 SHALL 提供固定 seed／版本可重現的 C 專用 fixtures、metadata 與示範設定，包含同次獨立試片、可配置子組及早於監控且 ID 不重疊的獨立歷史資料。這僅是測試準備，不代表已建立 SPC 界限；C Mock 欄位／子組大小 MUST 不成為 A 正式 CSV 必要契約。

#### Scenario: Mock 與其他來源結構不同
- **WHEN** 上傳來源沒有 C Mock 的子組或區段欄位
- **THEN** 仍可載入有效識別資料並回報缺少的候選輸入／本地識別限制，不自動湊連續五列、不要求 A 改格式，也不產生 X-bar 判定

#### Scenario: 已知異常與無效資料情境
- **WHEN** 載入 C 的正常、偏移／趨勢／同側、缺欄、缺值、無品質或無子組 fixtures
- **THEN** 來源／版本及預期資料可追溯，重建內容一致；預期真值在 metadata，介面僅載入／檢查，不宣稱已偵測異常或完成模型測試

### Requirement: DATA-04 正式來源轉接與交接成熟度

系統 SHALL 支援明確配置的欄名、單位轉換及時區映射，拒絕不支援單位／碰撞／錯誤設定，不要求其他來源採 C 欄名。Mock 產品規格與設定 MUST 明示示範用途，上傳來源不自動套用；正式 A／B 粒度、品質語意與模型契約仍標待整合，不能以測試上傳成功宣稱正式交接通過。

#### Scenario: 不同欄名與單位的測試上傳
- **WHEN** 使用者提供明確且有效的來源映射及單位／時區
- **THEN** 轉換後顯示來源與映射版本，資料問題可追溯；映射無效時不取代原有效資料

#### Scenario: 僅有 C Mock 或尚未正式整合的上傳
- **WHEN** 載入 C Mock 或尚未由 A／B 驗收的 CSV
- **THEN** Mock 設定與環境來源明示，上傳不自動套用 Mock 規格；正式資料／模型整合保持待確認，不妨礙本案資料檢視
