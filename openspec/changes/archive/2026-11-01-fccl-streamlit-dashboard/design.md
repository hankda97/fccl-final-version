# Design

## Context

C1＋C2 已有實作與 40 項 pytest 證據，見 DEV-20261101-012／013。使用者本輪要求將現有 Change 收斂為可獨立 Archive 的基礎交付，並先保全未完成功能。完整原設計 D1～D10 已在改寫前保存於 [歷史 design](../../../../docs/change-baselines/fccl-streamlit-dashboard-c1-c9/design.md)；後續歸屬見 [Roadmap](../../../../docs/CHANGE_ROADMAP.md)。

本設計描述目前已交付的邊界。與舊規劃有差異的僅是本案管理範圍，沒有重新開發或替換原功能。依據 ADR-010／013／014／015；ADR-003／012 的 Proposed 與所有 TCP 狀態保留。

## Goals / Non-Goals

**Goals:**

- 以已驗收的 UI／CSV 能力形成獨立交付，讓歸檔不依賴 C9。
- 保留原始資料、來源映射與錯誤追蹤；部分資料不足不阻擋可用的預覽。
- 把 28 需求／47 情境／39 任務的完整承諾與階段完成分開追蹤，不以縮小分母冒充全案完成。

**Non-Goals:**

本案沒有 SPC／預測／SHAP／Heatmap 計算、調參選取／策略、回放狀態機或正式 A／B 整合。也不控制真實機台、不訓練模型、不改隊友契約。不因資料與 Adapter 接點存在而宣稱後續能力已交付。

## Decisions

### D1. 已交付模組與執行環境

app.py 只組合 ui／state／adapters；資料解析與驗證分離在 c_dashboard/data 的 schema、loader、fixtures、session。不可用 Adapter 明示未接入，不提供公式預測。維持已驗證的 Python 3.11.17、Streamlit 1.66.1 與 requirements 鎖定環境，本次不改依賴。

所有未來模組如 spc、scenarios、alarms、plots、replay 的設計仍保存在歷史設計及各後續計畫，不屬本案待辦。未採把全部邏輯集中 app.py 的方案。

### D2. 主畫面、狀態與誠實占位

維持側欄、上方監控、四個原生 Tabs。上方快照／回放及播放控制仍停用，品質值為「—」，Alarm 尚未判定；What-if、圖表等標明階段與未實作。Data Tab 已可預覽與檢查。

業務狀態與 widget key 分開，同 Session 重跑與切 Tab 不重設資料／篩選。回放與 What-if 的容器只作未來接點；測試注入值保留不等於實際回放或調參完成。不同資料來源／內容／映射成功提交或實際篩選改變時清除相依狀態；同來源重載與未改篩選不清除。模型 artifact 身分保留，沒有模型切換業務流程。

### D3. 資料載入、來源映射與追溯

UTF-8／BOM 嚴格解析，顯式設定欄名、單位、時區；timestamp 與 product_batch 是 C 資料檢視的必要識別。缺區段用明示本地來源列 ID，不聲稱正式材料對齊；available_at 未提供時以 timestamp 作 C 內部假設並提示，正式語意仍須交接。

保留原始 bytes／字串／來源列，正規化空白、單位或排序逐項回報。無效時間／非有限數值／物理超界／缺值／疑似重複列都有 code、field、row、message。缺少品質欄保持缺欄；壞值正規化為缺值時保留原值與錯誤。重複列保留供檢查但不計入候選分析輸入。

檔案／映射失敗或沒有有效識別列時不替換舊有效資料；部分製程或品質不足可提交供資料檢視。功能表只顯示 C 特徵／品質／子組識別輸入完整度，沒有判定統計合理子組或模型可用。不能將此表當 SPC 或品質結論。

### D4. Fixtures、側欄與檢查呈現

固定 seed、版本化 C 測試 fixtures 與獨立歷史資料；歷史時間早於監控、樣本 ID 不重疊。n=5 與 25 個歷史子組是可配置 C 預設，已有其他組大小重建測試，不要求 A 採用。歷史資料僅備妥，未計算或驗證正式 SPC 基準。

側欄提供明確點擊載入的 Mock／上傳、JSON mapping、批號與含端點時間篩選。產品／配方示範規格僅隨 Mock 顯示，上傳不自動套用；環境顯示最新篩選有效識別列，缺值為「—」，不插值。材料長度不把同區段試片重複加總。

資料 Tab 預覽正規化資料與原始值（顯示上限 200 列），輸入完整度使用全篩選資料；匯入問題清單明示為整份檔案。這是快照檢查，尚無回放；C7 必須將預覽／問題／統計限制到共同可見範圍。

### D5. 分階段規格與獨立 Archive

先以原始 bytes 保存完整規劃，再建立六個後續計畫及需求／情境／任務矩陣，最後才縮小本案。原 C3～C9 的 checkbox 不留在本案，也不被勾成完成，仍是後續 31 項未完成任務。

本案只留下 dashboard-workspace／csv-ingestion 兩份基礎 delta。後續以當時主規格建立新增或完整 MODIFIED；不把原六份 ADDED 盲目同步。跨階段情境分別在功能／回放／正式整合時驗收，詳見 Roadmap。本案 8／8 與全案 8／39 必須並列說明。

### D6. 驗收證據

八項任務各自已有測試與指南；[基礎驗收對照](../../../../docs/C_BASE_ACCEPTANCE.md) 對應目前兩份 spec 的每個情境與測試函式。既有 40 項測試不修改、不以本輪文件變更宣稱新增功能。

本案完成只代表基礎 UI 與 C Mock／上傳載入層。C3 後每個 Change 都需自帶單元／UI／文件驗證；C8 是全流程驗收，C9 需正式來源／模型／SHAP 及團隊規則的獨立證據。

## Risks / Trade-offs

- [分母縮小被誤當全案完成] → Roadmap 保留原 39 項與全部 28／47 追蹤，列明尚餘 31 項。
- [未完成規格被 Archive 同步] → 本案 delta 僅描述已驗收基礎層，四份分析／回放 spec 移出 active Change 並保存在歷史快照。
- [舊歷史連結移位] → 日誌正文不改寫，Roadmap 列出原路徑到快照的對照；TCP 只追加管理補充，不改原狀態。
- [Mock／輸入完整度被當正式契約／SPC 結論] → 明確標示來源與限制，正式語意留 C9。

## Migration Plan

本次沒有程式、CSV、模型或執行環境遷移。先審查拆分文件、strict 及既有測試適用性；使用者確認後才依 Archive 技能同步這兩份基礎 delta 並歸檔。後續 C3 Propose 依新主規格建立，不能自動 Apply。

如需回查原規劃，讀取不可覆寫的歷史快照；不得為恢復規劃而把未完成六份 spec 整體同步為正式能力。

## Open Questions

沒有阻擋本案基礎交付的未決技術問題。A 正式欄位／粒度／可得時間、B 特徵／前處理／輸出／SHAP、正式品質來源／NG 門檻／多目標原則仍由 C9 與 TCP-001～004 追蹤，不改既有團隊討論狀態。
