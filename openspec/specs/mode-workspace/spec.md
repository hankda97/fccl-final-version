# mode-workspace Specification

## Purpose

在保留 AI 品質預測為核心的前提下，將歷史分析、測試線實驗及產線擾動補償分成可辨識、狀態及來源互不污染的工作模式；以明確待交付接點支持後續模擬與歷史回放，不將提案或測試替身誤稱已完成的產線能力。

## Requirements

### Requirement: MW-01 三模式定位與成熟度導航

系統 SHALL 提供模式 A「AI 品質預測與關鍵因子分析」、B「測試線動態參數實驗」、C「現場產線波動與動態線速補償」的明確導航，預設 A。模式 A MUST 保留 C1～C7 已交付能力；B／C 僅有工作區與接點時須明示尚未交付，不得自動產生模擬結果或暗示真實產線接入。

#### Scenario: 預設進入核心模式
- **GIVEN** 新工作階段且未選應用模式
- **WHEN** 開啟儀表板
- **THEN** 預設模式 A，原 CSV／Mock、五目標預測、SPC、Alarm、固定 What-if、Heatmap、兩種 SHAP 及 C7 回放入口均保留，依實際資料與模型能力顯示結果或既有不可用原因；七表正式投影及模型接點仍按 C9 成熟度標示，不宣稱已整合

#### Scenario: 未交付的模擬模式入口
- **GIVEN** B／C 完整模擬後端尚未交付
- **WHEN** 選擇模式 B 或 C
- **THEN** 顯示該模式定位、模擬標示、後續 Change 與不可用原因；不借用 A 的預測／SPC／Alarm 作該模式結果，投入批次／補償等未交付動作停用

#### Scenario: 返回模式 A 保留全部能力
- **GIVEN** A 已載入資料並完成可用的分析，且曾檢視 B／C
- **WHEN** 返回模式 A
- **THEN** A 的側欄、四 Tabs、五目標及原分析流程保持可操作，已完成能力不因新增導航而被替換、刪除或要求重新訓練模型

### Requirement: MW-02 模式工作狀態隔離與相容

每個應用模式 MUST 分別保有資料／篩選、情境／解鎖、回放或實驗識別、SPC、模型、Alarm、圖表及歷史事件狀態；模式切換不得清空或改寫其他模式。既有單一工作階段 SHALL 可保留為 A；B／C 初始化不得複用可變物件、資料列或由 A 自動複製批次作實驗。模擬 run 的重設不得刪除 A 原始資料或其他 run 的歷史紀錄。

#### Scenario: 同名識別不造成共享狀態
- **GIVEN** A、B、C 的測試上下文刻意使用相同檔名、批號、卷別與區段 ID
- **WHEN** 在 B 更新其測試資料、候選參數或解鎖狀態
- **THEN** A／C 的資料與候選、SPC 界限、事件、模型結果與圖表均不變；相同事件／樣本 ID 仍按 mode／run 分辨，B 的控制不寫入 A 的歷史 CSV、generated_data/v2 或 C 的事件儲存

#### Scenario: 切換保留各自工作
- **GIVEN** 三模式各有不同的測試狀態與來源版本
- **WHEN** 在 A、B、C 間切換並觸發一般重跑
- **THEN** 各模式的有效來源、篩選、選定區段、候選與匹配結果可恢復；顯示值由目前模式取得，不因 widget 名稱相同而交換參數

#### Scenario: 資料重設只影響指定模式
- **GIVEN** A 與 B 都已有有效工作狀態
- **WHEN** A 成功載入不同資料或改變其篩選，或 B 明確重設自己的測試 run
- **THEN** 僅依該模式規則重設相依狀態；其他模式保持不變，失敗載入亦不得取代該模式先前有效資料，既有歷史事件仍按原 run 追溯，不透過重設刪除其他模式／run 或寫回七表

#### Scenario: 舊工作階段保留為模式 A
- **GIVEN** 已有 C1～C7 單一工作階段的資料、固定 What-if、SPC／圖表結果及回放進度
- **WHEN** 首次建立三模式管理狀態或再次執行初始化
- **THEN** 原內容及 C7 游標／時間 profile 保留於 A 且不重複初始化；B／C 為獨立空工作區，不被宣稱有歷史量測或正式模型輸出，不因初始化產生模擬資料

### Requirement: MW-03 分離來源、監控與模型結果

資料與結果 SHALL 帶有模式、工作階段／run、來源與設定版本及材料／時間識別，SPC 基準、Alarm 去重及圖表／預測快取 MUST 按模式隔離。模擬真值、模擬量測、模型預測與固定候選須可辨識，不能因共用元件把模擬資料送入 A 的實測監控或把品質規格當管制界限。

組長七份 CSV MUST 維持唯讀，B／C 額外資料由 C 獨立模擬來源提供並標示 Synthetic／Mock；不得回寫七表、不要求 A 重產或改 B 正式模型契約。模型來源／版本與輸入資料來源 SHALL 分開標示，模擬效果不得宣稱經真實製程因果驗證。

#### Scenario: SPC 與警報不跨模式聚合
- **GIVEN** A 與 B 測試資料含相同事件 ID／規則，但各自具有不同基準與來源
- **WHEN** 顯示其中一模式的監控摘要與 Alarm
- **THEN** 只顯示目前模式／run 的結果、來源及界限，SPC／AI／未來訊號品質事件按種類分辨，去重不吞掉另一模式的事件，不自動套用 A 的基準至 B／C；缺乏有效獨立基準時明示無法判定，不把缺資料當正常

#### Scenario: 模擬、候選與真值分開
- **GIVEN** 測試接點回應包含製程觀測、延後可用的模擬量測及獨立模擬真值
- **WHEN** 將回應轉接為可檢視資料或模型輸入
- **THEN** 來源標示 Synthetic／Mock、simulator／設定版本及 mode／run；事件、模擬製程、原始訊號、處理後訊號、模擬量測、隱藏真值及預測分開，時間／站別／批次／卷／MD 可追溯；隱藏真值、噪音真因與未到可得時間的特徵／量測不流入分析；What-if 候選不改歷史，不回寫七表，不宣稱真實因果

#### Scenario: 模型與圖表快取按模式失效
- **GIVEN** 兩模式使用相同模型 artifact 但輸入來源／run 或設定不同
- **WHEN** 來源、逐目標 availability、模型／manifest 或圖表條件改變
- **THEN** 僅重算該模式相依結果；另一模式的快取不能冒充新結果；分別標示輸入資料來源、正式模型／公式 Mock／render-test 的版本及逐目標預測／標籤／解釋能力，正式模型處理 Synthetic 輸入也不稱真實實測，未校準 Mock risk 不改稱正式 NG 機率

#### Scenario: 舊請求與錯誤路由拒收
- **GIVEN** 某模式曾送出請求，之後切換模式、重設 run 或變更資料
- **WHEN** 收到舊請求或未知／錯誤模式的回應
- **THEN** 拒收不匹配回應並顯示原因，不寫入目前模式或覆蓋較新結果；來源錯誤只影響相依功能，不清空其他模式

### Requirement: MW-04 未來模擬接點與共用服務邊界

系統 SHALL 提供可選、版本化的 B／C 模擬能力接點，沿用既有預測與 What-if／SPC／圖表服務的顯式輸入邊界。未提供後端時回報不可用；測試替身只驗證資料路由與來源／單位／時間，不代表完整實驗、擾動、濾波或補償已交付，不新增 A／B 正式欄位義務或機台控制。

本 Change MUST 僅交付導航／隔離及接點，完整 C 端測試線與產線模擬器、獨立資料持久化留後續兩案。任何回應不得新增正式模型特徵或以模擬器結果冒充正式模型輸出。

#### Scenario: 模擬後端未提供
- **GIVEN** 只有既有 C Model Adapter，未注入 B／C 模擬後端
- **WHEN** 取得模擬能力描述或嘗試未支援動作
- **THEN** 明確回報模式、能力及不可用原因，不以 A 的 CSV 充當新 run，不默默啟動生成器或修改機台

#### Scenario: 明確標示的接點替身
- **GIVEN** 注入固定且標為介面測試的 B 或 C 接點回應
- **WHEN** 驗證並轉交共用服務
- **THEN** 保留 Synthetic／Mock 標籤、模式／run／模擬器與設定版本、Timestamp、站別、批次／卷／MD、事件／量測／特徵可得時間及單位；只有當時已可得且被模型明確支援的製程特徵交給既有 Model Adapter，模擬真值／量測／模型預測通道不混淆，五目標能力不足逐項回報；替身不操作正式檔案或持久化模擬器

#### Scenario: 不完整或不相容的回應
- **GIVEN** 接點回應缺少模式／run 識別、單位或時間，材料區間無效，或 schema／來源不相容
- **WHEN** 請求將該回應提交工作區
- **THEN** 回報結構化問題並拒絕提交，保留原有效資料；不得猜測單位、MD 對齊或把部分欄位靜默補造為真實品質值

#### Scenario: 調參意圖不等於已執行補償
- **GIVEN** 接點描述區分候選、人工確認的模擬參數事件及其影響材料範圍
- **WHEN** 只調整 What-if 候選或後端回報該動作尚未實作
- **THEN** 不產生已執行實驗／補償紀錄，不推定線速降低必然改善；未來事件須追溯確認時間、參數差異與受影響 MD／站別，保留原始訊號及補償紀錄，後續模擬量測依其可信可得時間才顯示，不以候選預測回填量測，且明示 Synthetic／Mock／非機台控制

### Requirement: MW-05 與歷史回放的獨立性

應用模式 A／B／C MUST 與模式 A 內的快照／歷史回放分開。已交付 C7 的單游標、播放控制、可信逐欄位／逐目標可得時間與禁止未來資訊規則 SHALL 完整保留；本案只整合隔離與生命週期，不重做 C7 引擎，不將未交付 B／C 模擬時鐘宣稱為可用。

#### Scenario: 回放不適用來源仍可使用模式 A
- **GIVEN** C7 已交付，但模式 A 目前來源缺可靠的可得時間或時間映射
- **WHEN** 顯示模式導航或用固定前綴的測試接點呼叫共用分析
- **THEN** A 的快照檢查及其他可靠功能仍可用，只停用不適用的回放／目標並顯示原因，不退回所有來源的回放占位、不猜時間或套固定延遲；有界接點不讀未來資料，模擬接點替身不冒充完整 B／C 引擎

#### Scenario: 離開模式時暫停而不歸零
- **GIVEN** A 已使用 C7 回放並有游標及播放狀態
- **WHEN** 離開 A 後返回，或收到離開前的時間事件
- **THEN** 離開時暫停、保留進度及有效固定區段，返回不自動播放，舊時間事件不推進游標；B／C 不消耗 A 的回放事件或倍率

#### Scenario: C7 重播接點不重設其他模式
- **GIVEN** A 有 C7 回放狀態，B／C 各有獨立測試 run
- **WHEN** 重新開始 A 的回放輪次或透過相同生命週期接點重設
- **THEN** 只有 A 的相依可見結果／失效情境依 C7 正式規格處理，不自動復活未播放區段的 What-if；固定 SPC 基準、原 CSV 與 B／C 歷史／run 不被重估或重置；沿用既有 C7 控制，不新增 B／C 模擬引擎
